## Source trace and limits

Both the normal Events API and AI list gateway call `svc.athlete.event.list` with the athlete ID and scope. The direct single-event lookup uses a different competition request. The successful direct lookup explains why other event reads may work while discovery fails.

In the inspected AI source, `AthleteGateway.list_enterable_events` validates `AthleteEventsReply` and converts every returned event through `entry_event`. Its tool wrapper turns a timeout or unexpected exception into `unavailable`; the RPC helper also maps service failures to that result. Consequently, a response-model mismatch, a conversion exception on any list item, an RPC failure or a time-budget expiry can all produce the same observed answer. A bad item elsewhere in the list could affect Taiwan discovery; this is a hypothesis, not a verified malformed record.

The inspected AI default tool timeout is 1.5 seconds; the BFF RPC default is 2 seconds. This difference is a candidate to investigate, not proof of a timeout. The working HTTP timings do not establish AI-side execution time. The inspected source checkout is not independently confirmed as the deployed revision.
