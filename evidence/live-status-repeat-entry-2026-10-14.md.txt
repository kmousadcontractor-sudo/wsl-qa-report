# Live rendering and repeat registration — 14 October 2026

Two visible dev journeys were executed: the existing single-event membership journey with stricter frontend checks, and one new regional-membership journey. The report keeps one record per Java test method. Earlier minor/age-boundary results remain labelled with their own execution sources.

The new assertions do not equate a backend state with a rendered state. An event-list tab is mounted before registration, remains open throughout the journey, and is checked for Waitlisted and then Confirmed without refresh, navigation, filter changes or query invalidation. After Confirm & charge, the manager stays on Athletes while the script waits for the visible Confirmed and Collected labels. API checks are separate. DOM reads pump browser events; they do not refresh the page.

Back-navigation steps use the actual Back to Events link, verify the event list, then traverse browser history back through confirmation to the registration form. The single-event scenario resubmits unchanged valid data; the regional scenario changes the event reminder phone to another valid US number and resubmits. A successful repeat must reuse the same entry ID, and its accepted request must contain the edited phone. A submitted request alone is not reported as successful registration.

## Trace interpretation

For each failed check, compare the expected visible label with the recorded DOM text and the separately logged backend state. If the API has Collected while the row has Pending, the observed defect is stale frontend rendering; successful backend collection does not make the frontend assertion pass.

The checked-out frontend's useAthleteEvents query has no periodic refetch configured. Its useConfirmField hook invalidates the seed list when confirmation is accepted, while charges complete asynchronously. These are code leads consistent with stale status rendering, not proof of the exact deployed dev revision or root cause. No application code, cache invalidation or manual refresh was used to make these assertions pass.
