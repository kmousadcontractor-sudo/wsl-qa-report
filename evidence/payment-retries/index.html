What the manual retries actually exercised

The saved test card was invalidated after its original generic decline. Later retries can be accepted by the API yet produce payment not attempted, rather than a new processor decline. The passing checks establish request handling and idempotency; they do not prove repeated Stripe charge attempts.

Two requests with the same key both returned HTTP 200 but produced only one new outcome. Two parallel requests with different keys returned HTTP 409 and HTTP 200, with one accepted claim.

Earlier withdrawal issue remains unresolved

The earlier immediate post-withdrawal request returned HTTP 200. In the valid-card scenario, application history recorded payment success above withdrawal. In this later run, settled withdrawn entries reject retries with HTTP 409.

That difference does not establish a fix: the lifecycle state and elapsed time differ. The race between card replacement, retry dispatch and withdrawal still requires bus/provider correlation.
