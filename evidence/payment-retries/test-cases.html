Payment retry test cases and edge-case matrix

110 designed cases · All Not run

20 October 2026. This matrix is not an execution report. Earlier passing checks do not establish coverage of every case below.

Baseline

Version 16: retries 24/72h; notices 24/72/120/168h; grace 168h; cutoff 10 days before event. All offsets start at the first failure.

T0 = 20 Oct 2026, 12:00 UTC. Baseline event = 20 Nov. UTC cutoff = 10 Nov 00:00. Effective deadline = min(T0 + 168h, cutoff) = 27 Oct 12:00 UTC.

Boundary cases run at −1ms, exact instant and +1ms. Use separate isolated fixtures per branch. A generic inactive card does not establish retryable provider behavior.

How to execute and collect proof

Run timing arithmetic with an advanced local clock; locks/outbox/idempotency with real integration infrastructure; and user flows with dev APIs/UI plus genuine provider test events. Keep those execution layers separate.

Capture policy version, T0/deadline, entry/charge/organisation IDs, idempotency keys, execute/release/outcome correlation, provider attempt IDs, before/after rows, UI/history and notification delivery evidence. “HTTP 200”, “attempt sent” and “payment collected” are separate assertions.

For scoped dev timer acceleration preserve UUIDs, record before/after timestamps, confirm worker access and retryable classification. Do not modify global rules. No dev database change is part of this matrix.

Decisions required before sign-off

  • DEC-01: Strict event cutoff versus late tolerance. Should a scheduled retry be allowed after event-minus-10-days when it was due before cutoff? Current _work permits bounded late dispatch.
  • DEC-02: Retry exactly at effective deadline. Current due<=deadline logic can dispatch at deadline before flagging. Confirm intended policy.
  • DEC-03: Business timezone. Current event_starts_at uses UTC midnight. Confirm venue-local versus UTC cutoff interpretation.
  • DEC-04: Queued reminder after settlement. Confirm suppression or rewording rules for already queued reminders.
  • DEC-05: Archived/cancelled events. Confirm retry stop and financial reconciliation policy for these event states.

Requirement = intended acceptance criterion. Current code = implementation behavior to verify, not a product decision. Product decision = expected result needs agreement before pass/fail.
