Beach Marshal shows no error when a completed reply contains no text (simulated response)

Reproduced under controlled conditions · Dev · 27 October 2026 · Suggested P3

What we tested: A test script supplied an empty reply instead of the real AI. The real website then showed no answer and no explanation. This report concerns frontend handling, not the real model’s answer.

Simple steps

  1. Sign in to the dev website with an account that can open Beach Marshal.
  2. Install the attached simulate-empty-reply.js fixture in this tab using the browser DevTools Console. This makes the test script supply the reply instead of the real AI.
  3. Open Beach Marshal and select New conversation.
  4. Type "Hello QA empty reply test" and send it.
  5. Wait at least six seconds after sending.
  6. Observe the chat: only the sent message remains; there is no answer, error or retry guidance.

Cleanup: run window.qaEmptyReplyTest.restore() in Console, or refresh the tab.

Developer setup: copy the browser-only fixture

Open DevTools → Console in the signed-in app tab and paste this code. It affects only this tab. The automated test sends no real model request.

(() => {
  if (window.qaEmptyReplyTest) throw new Error('Fixture already installed; restore it first.');
  const originalFetch = window.fetch.bind(window);
  const test = window.qaEmptyReplyTest = {mode:'empty',calls:[],restore:()=>{window.fetch=originalFetch;delete window.qaEmptyReplyTest;}};
  window.fetch = async (input, init) => {
    const url = typeof input === 'string' ? input : input instanceof URL ? input.href : input.url;
    if (!new URL(url, location.href).pathname.endsWith('/assistant/run')) return originalFetch(input, init);
    const request = JSON.parse(init.body), messageId=crypto.randomUUID(), started=performance.now();
    const call={at:new Date().toISOString(),mode:test.mode,request,events:[]};test.calls.push(call);
    const stream = new ReadableStream({start(controller){
      const emit=event=>{call.events.push({ms:performance.now()-started,event});controller.enqueue(new TextEncoder().encode('data: '+JSON.stringify(event)+'\n\n'));};
      emit({type:'RUN_STARTED',threadId:request.threadId,runId:request.runId});
      emit({type:'TEXT_MESSAGE_START',messageId,role:'assistant'});
      setTimeout(()=>{
        if(call.mode==='recovery')emit({type:'TEXT_MESSAGE_CONTENT',messageId,delta:'QA recovery check: reply text is displayed. This is a test response, not the real AI.'});
        emit({type:'TEXT_MESSAGE_END',messageId});
        emit({type:'RUN_FINISHED',threadId:request.threadId,runId:request.runId});
        controller.close();call.finishedAt=new Date().toISOString();
      },250);
    }});
    return new Response(stream,{status:200,headers:{'Content-Type':'text/event-stream'}});
  };
  console.info('QA empty-reply fixture installed. Real assistant requests are replaced only in this tab. Restore with qaEmptyReplyTest.restore().');
})();

Actual result

The chat stops waiting and the message box becomes available again. Only the user’s message is visible. No answer, explanation or retry guidance appears.

Expected result

Detect that the finished reply contains no answer text. Show a clear explanation and an actionable retry option, rather than silently ending. Example wording: “We couldn’t generate a response. Please try again.” Exact wording and UI are a proposed QA expectation for product confirmation.

User impact

The user cannot tell why there is no reply. They can send another message manually; the page remains usable.
