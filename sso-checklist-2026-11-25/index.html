Parts 2–9 need the switch on: ask the developers when it's on and which address the sign-in host uses.

How to mark each row: ✅ pass · ❌ fail (add a screenshot) · ⏭ not run (say why)

Part 1: Regression now (SSO off): nothing that worked before is broken

  • Existing athlete signs in with email + password at https://app.dev.worldsurfleague.com/login
  • Tour Manager signs in and lands in the Tour Manager app (Events)
  • Wrong password: a generic error that doesn't say whether the account exists
  • Sign out, then the back button doesn't show signed-in pages
  • Sign up a new account: Dev now asks you to verify your email first (202 "verification required"). The verification email arrives.
  • Verification link works once; a second click is refused; an older link is refused after Resend
  • You can't sign in before verifying; after verifying you can
  • Forgot password: the email arrives, the link works once and expires, and the new password works
  • Registration, membership purchase and event entry still work end to end for a new athlete

Part 2: Hosted sign-in pages (needs SSO on)

  • Log in in the app takes you to the hosted sign-in page on the sign-in host, then back to the page you started from
  • Hosted sign-up, reset password, logout and error pages open and look right (WSL Pro branding, both languages you try)
  • After sign-in you return to the right app (athlete → athlete app; Tour Manager → Tour Manager app)
  • Sign-out ends the session everywhere (app and hosted pages). Signing in again asks for credentials.
  • A changed or foreign return address is refused (no open redirect): try ?redirect=https://example.com
  • Refreshing a page after the session token expires keeps you signed in (refresh works); after sign-out it doesn't

Part 3: 6-digit email code sign-in (needs SSO on)

  • Email me a code: a 6-digit code arrives from the new sign-in sender address
  • The right code signs you in; it works once
  • A wrong code is refused; after several wrong codes the code locks (note how many)
  • An expired code is refused (note how long it lasts)
  • Resend: the older code stops working
  • A code for account A can't sign in account B
  • Email matching ignores case and leading/trailing spaces
  • For an address with no account, the page doesn't say whether the account exists

Part 4: Accounts with no password, "Create your password" (needs SSO on)

  • An imported old-site or Facebook-only account signs in with a code, then is asked to create a password
  • Password rules are shown and enforced (too short or too weak is refused)
  • After creating it, password sign-in works
  • A Dev athlete with no password (the WSL-10809 case) gets the same prompt in the app

Part 5: Hosted sign-up and email verification (needs SSO on)

  • Hosted sign-up creates the account. Per IAM #102, hosted sign-up sends no verification link: the first code sign-in verifies the address, and verification never blocks sign-in.
  • Optional terms step: shown when needed; you can't continue without accepting
  • Marketing consent choice is saved (opted in vs not)
  • Signing up again with an existing email: you're told the account exists (or a code is sent), and no duplicate account is created

Part 6: Staff accounts (needs SSO on)

  • Tour Manager, admin and Finance accounts must use a password. A code sign-in doesn't give staff access (IAM: "staff roles need a password sign-in").
  • A staff member signed in with a code doesn't gain Tour Manager or admin access after a token refresh
  • Tour Manager 102 (no Finance role) still can't edit the Finance cards in Settings

Part 7: Emails (needs SSO on)

For each email: it arrives, the sender is the new sign-in identity, the subject and wording are right, it's in your language (try fr and ja in browser settings), and links work once.

  • Email code
  • Reset password
  • "An account already exists" notice (sign-up with an existing email)
  • Verification (current app sign-up)

Part 8: TV sign-in (device flow) (needs SSO on, if a TV client is available)

  • The TV shows a code; approving on a phone signs the TV in
  • Approving on a phone with no session goes through the normal sign-in pages first
  • A denied or expired TV code is refused

Part 9: Account page /api/me and the admin console (needs SSO on)

  • A fan account can see and edit its own details; changing email needs a code to the new address
  • Password change from the account page works; the old password stops working
  • Account erase request is accepted and recorded
  • Admin console: search by old-site id (digits only, exact), and the account detail shows consents, live sign-ins and the last 50 sign-in audit rows

Notes

  • Use fresh Mailosaur addresses on the current Dev server for new accounts.
  • Record the sign-in host URL, and any 4xx/5xx, with a screenshot.
  • Prod is out of scope: SSO isn't there.
